**Goal:** Release ArkScope's complete `zh-Hant` / `en` interface by adding one
Settings PageHeader locale selector, proving the existing durable locale
authority end to end, and closing the final bilingual, responsive,
formatter-freeze, and read-only production gates.

**Architecture:** Keep the existing locale controller, provider, cache,
profile API, and synchronous bundled resources unchanged. A Settings-local
controlled native `<select>` reads `useUiLocale()`, renders fixed-locale
autonyms from resource bundles, and delegates supported changes only to
`controller.setLocale()`. Existing direct-Settings suites receive a test-only
real provider/controller wrapper; no production fallback is introduced. All
other application behavior, source/generated content, formatters, and CSS are
frozen unless a measured visual failure triggers the reviewed stop process.

**Tech Stack:** React 18, TypeScript 5.9, i18next 26.3.6 selector API,
react-i18next 17.0.10, Vitest 4/jsdom, Vite/Electron, the TypeScript-AST
visible-literal scanner, pytest, SQLite profile authority, and isolated
Chromium CDP runtime gates.

## Independent Implementation-Review Repair Resolution

Independent re-review reproduced every original correctness gate, then found
two issues outside the original evidence shape. Both are accepted for bounded
repair before merge:

1. The renamed foundation guard expanded selector-placement coverage to all
   production files but dropped the old repo-wide `changeLanguage\s*\(` and
   `(?:locale|language)-selector` dimensions. Strengthen the existing renamed
   node in place. It must scan `productionFiles("src")`, allow direct
   `changeLanguage()` only in `src/main.tsx`, `src/test/setupI18n.ts`, and
   `src/test/testUiLocale.tsx`, and forbid kebab selector ownership outside the
   two reviewed selector files. Prove the guard with a temporary production
   mutation that makes the unchanged node fail, then remove the mutation.
   Node accounting does not change.
2. English `Currently unavailable` is clipped inside
   `.credential-status-pill` because the generic masked-key rule caps every
   `.credential-row > .key-pill` at `96px`. A mounted repair probe then proved
   that the same span/class also carries the masked token for an available
   credential, so an unconditional class override would silently widen the
   protected masked-key presentation. The release therefore owns one more
   precise scoped override:
   `.credential-row > .credential-status-pill.missing { max-width: none; }`. Add one
   RED-first Shell CSS node named
   `lets credential availability status use full localized copy without widening masked keys`.
   The test must retain the generic `96px` cap, prove the dedicated class plus
   existing `missing` state are wired, and require only the unavailable-status
   override. Available masked values remain capped. No JSX, resource, or
   formatter behavior changes.

The second repair is preferable to backlog deferral because I18N-6 makes the
English Settings state publicly reachable for the first time. Its element-level
browser gate must require `scrollWidth - clientWidth <= 1` for every visible
localized unavailable-status `.credential-status-pill.missing` in both locales
at `390`, `760`, `1024`, and `1440`. It must separately prove that an available
masked credential retains computed `max-width: 96px`; intentional truncation of
that masked token is not a status-copy failure. The same census excludes
visually hidden nodes, non-leaf layout containers, and `overflow: visible`; it
supplements rather than replaces document-overflow checks.

Revised raw accounting is `+12/-4`, final frontend is `95 files / 1056 nodes`,
focused is `13 files / 148 nodes`, and Shell CSS is `11/11`. Resources, scanner,
backend, controller/provider/bootstrap, formatters, and all other CSS remain

## Locked Decisions

1. Public locales remain exactly `zh-Hant` and `en`. No Simplified Chinese,
   detector, or locale inference is added.
2. Exactly one selector mounts in Settings `PageHeader.actions`; it is not a
   registry section, workflow tab, Shell/topbar control, or shared primitive.
3. `src/settings/LocaleSelector.tsx` uses `useUiLocale()` and never calls
   `changeLanguage`, API, storage, or cache directly.
4. Active-locale label comes from `settings.locale.label`. Both options use the
   same `settings.locale.selfName` key through fixed `zh-Hant` / `en`
   translators, yielding `繁體中文` / `English` in every interface locale.
5. Fixed translators run during render after bootstrap, not at module
   evaluation.
6. `SUPPORTED_UI_LOCALES` owns order; `isUiLocale` validates DOM values.
7. Busy disables the control and controller busy remains the second guard.
8. PUT failure rolls back first; `writeFailed` then renders in the restored
   locale with no raw detail and clears on successful retry.
9. Switching preserves route, mounted nodes, focus, drafts, query, Drawer,
   disclosures, in-flight work, source/generated/manual-translation content,
   and formatter output.
10. The only request caused by a real switch is
    `PUT /profile/settings/ui-locale`; cache writes only after authority success.
11. Cache-first startup, durable correction, StrictMode coalescing, and
    user-operation precedence remain unchanged.
12. `ui_locale` controls copy only. All 20 formatter owners remain frozen.
13. The review-measured English credential-status clipping authorizes exactly
    one scoped `styles.css` override and one RED-first Shell CSS node. No other
    CSS change is allowed.
14. Production closeout may locate but must not operate the selector. The
    user's first real selection owns the first production write.

  import {
    SUPPORTED_UI_LOCALES,

      if (busy || !isUiLocale(next) || next === locale) return;
      void setLocale(next);
    };
    return (

        <label>
          <span>{label}</span>
          <select aria-label={label} value={locale} disabled={busy} onChange={onChange}>
            {SUPPORTED_UI_LOCALES.map((value) => (
              <option key={value} value={value}>{localeSelfName(value)}</option>
            ))}
          </select>
        </label>
        {errorCode === "write_failed" ? (

          </span>

      </div>
